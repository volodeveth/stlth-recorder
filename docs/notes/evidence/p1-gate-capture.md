# Ворота P1: захоплення на реальному залізі

**Дата:** 2026-08-16
**Машина:** Windows 11, 10.0.26200
**Пристрої:**
- вхід — Microphone Array (Intel® Smart Sound Technology for Digital Microphones),
  рідний формат **IEEE_FLOAT 48000 Гц, 4 канали, 32 біт**, гучність 74%
- вихід — Speakers (Realtek(R) Audio), рідний формат IEEE_FLOAT 48000 Гц, 2 канали,
  32 біт, гучність 8%

Обидва пристрої працюють на 48 кГц, тож частоту міняти не доводиться. Мікрофон віддає
чотири канали 32-бітного float — тобто шлях конвертації виконується на звичайному
ноутбуці з першого запуску, а не лише «на випадок екзотики».

## Проба 1: тиша

`stlth-cli probe 6`, під час якої нічого не грало.

```
system: пакетів 0,   пристрій «Speakers (Realtek(R) Audio)», qpc від драйвера, справжнє аудіо: ні
   mic: пакетів 627, пристрій «Microphone Array (Intel...)»,  qpc від драйвера, справжнє аудіо: так
```

**Loopback не віддав жодного пакета за шість секунд**, поки мікрофон видав 627. Це не
збій — це його природа. Саме тому довжину доріжки визначає таймлайн сесії, а не потік,
і саме тому watchdog дивиться на годинник пристрою, а не на лічильник пакетів.

## Проба 2: під звук

`stlth-cli probe 8` під час програвання тону 440 Гц.

```
[system] #0     t=  0.0210 с  кадрів=480   крок=—
[system] #1     t=  0.0309 с  кадрів=480   крок=9.97 мс
[   mic] #0     t=  0.2063 с  кадрів=480   крок=—
[   mic] #1     t=  0.2163 с  кадрів=480   крок=9.98 мс
[system] #800   t=  8.0210 с  кадрів=480   крок=9.97 мс
[   mic] #800   t=  8.2063 с  кадрів=480   крок=10.03 мс

system: пакетів 819, qpc від драйвера, справжнє аудіо: так
   mic: пакетів 826, qpc від драйвера, справжнє аудіо: так
```

| Що перевіряли | Результат |
|---|---|
| `qpcPosition` від драйвера | заповнений **обома** пристроями, монотонний |
| Крок між пакетами | 10.0 ± 0.15 мс на обох потоках |
| Спільність шкали | так: потоки стартують у різні моменти (0.021 с і 0.206 с) на одній осі |

Різниця стартів — це рівно те, що заливає тишею `TimelineAccountant`, і рівно те, що
зробило б доріжки різної довжини без нього.

## Проба 3: запис 30 секунд

`stlth-cli record 30` під тон.

**Перший прогін** (інкрементний облік таймлайна):

```
Тривалість: 30.545 с
mic.wav:    1 466 170 кадрів
system.wav: 1 466 168 кадрів
Різниця:    2 кадрів (0.0 мс)
```

Дві кадри — 42 мкс. Величина смішна, природа її ні: облік округлював позицію на
кожному пакеті, і похибка накопичувалася. На годинній розмові це вже не два кадри.

**Другий прогін** (після переходу на абсолютний облік від початку сесії):

```
Тривалість: 30.546 с
mic.wav:    1 466 220 кадрів
system.wav: 1 466 220 кадрів
Різниця:    0 кадрів (0.0 мс)
Режим:      qpc-anchored
Звук співрозмовника: є
```

Вміст файлів (`tools/wav_stats.py`):

```
mic.wav:    1,466,220 кадрів (30.546 с), 1 кан., пік 0.000, RMS 0.0000, тиші 100%
system.wav: 1,466,220 кадрів (30.546 с), 2 кан., пік 1.000, RMS 0.7002, тиші 1%
```

Системний канал записав тон чисто. Мікрофонний практично мовчить — кімната тиха, а
динаміки на 8% гучності, тож акустичного зв'язку майже немає. **Рівень мікрофона на
живій мові цим не перевірений.**
